# Workshop 1: IT Troubleshooting Challenge

Welcome to the IT Troubleshooting Challenge! In this hands-on 3-hour lab, you will learn practical approaches to resolving computer incidents using a structured methodology.

## Aim
Resolve computer incidents using a structured methodology of diagnosis, intervention, and verification.

## Learning Objectives
By the end of this workshop, you will be able to:
* Follow a repeatable troubleshooting process instead of guessing.
* Collect relevant information and distinguish symptoms from causes.
* Use basic Linux diagnostic commands in an Ubuntu Desktop virtual machine.
* Apply a controlled fix and verify that the service or application works again.
* Record actions, results, and evidence in a clear technical incident report.
* Work collaboratively and communicate technical findings.

## Workshop Format
* **Duration:** 3 hours (180 minutes)
* **Team Size:** 4-5 students per team
* **Environment:** Ubuntu Desktop virtual machine (via Oracle VM VirtualBox)

## Folder Structure
* `Student-Guide/`: Contains the Student Workbook, Incident Cards, and Diagnostic Checklist. Start reading these to understand your tasks and methodology.
* `Worksheets/`: Contains blank templates you will need to fill out during the lab: the Incident Log and the Final Report Template.
* `Assets/`: Contains any sample files needed for the lab exercises.

## Team Roles
To ensure everyone participates, your team should divide into the following roles (rotate technical roles between incidents):
1. **Team Coordinator:** Keeps the team on task, reads the incident brief, and ensures decisions are agreed upon.
2. **Lead Technician:** Runs diagnostic commands and performs approved changes.
3. **Evidence Recorder:** Writes down symptoms, commands, outputs, and timestamps.
4. **Verifier / Tester:** Defines and performs the tests that prove the fix worked.
5. **Reporter** *(for teams of 5)*: Prepares the final explanation and presents the results. (If a team of 4, combine with the Coordinator role).

## The Troubleshooting Methodology
1. **Identify:** Understand the problem.
2. **Gather evidence:** Observe and collect facts before changing anything.
3. **Form a hypothesis:** Identify the most likely cause.
4. **Test the hypothesis:** Run a low-risk test.
5. **Implement a fix:** Make one controlled change at a time.
6. **Verify:** Repeat the original test and perform a related test.
7. **Document:** Record the cause, fix, and evidence.

---
**Safety Note:** 
All work must be done inside the disposable Ubuntu VM. Do not perform disruptive tests on the host computer or the school network. Do not guess IP addresses or change settings without teacher approval.

## 1. Module Overview
This module provides foundational concepts, prompt engineering patterns, and verification practices for integrating Large Language Models (LLMs) and AI assistants into IT support, diagnostics, and script automation workflows. It serves as the technical reference base for **Workshop 2: AI IT Technician Assistant**.

## 2. Core Principles for IT Technicians Using AI
1. **Context-Rich Prompting (Symptom → Environment → Evidence):**
   * Never paste a generic error message alone. Always include the operating system, service/software version, recent configuration changes, and exact log or CLI outputs.
2. **Structured Output Requests:**
   * Ask the AI to rank root causes by probability, list non-destructive verification commands first, and clearly separate diagnostic checks from state-changing fixes.
3. **Zero Blind Execution ("Trust, but Verify"):**
   * AI models can hallucinate non-existent flags, deprecated commands, or destructive operations (`rm -rf`, `chmod 777`, `ufw disable`). Every command or script generated by an AI assistant must be read, understood, and tested in a safe sandbox before running on production systems.
4. **Data Privacy & Sanitization:**
   * Strip passwords, API keys, private IP mappings, customer PII, and proprietary configuration secrets from logs before submitting them to external AI tools.

## 3. Recommended Diagnostic Prompt Template

```text
Role: Senior Linux & Network Systems Engineer.
Environment: [OS / Version, e.g., Ubuntu 22.04 LTS Server, Apache2 / systemd]
Reported Symptom: [Clear description of what is failing and since when]
Diagnostic Evidence:
[Paste sanitized output of systemctl status, journalctl, ip a, ss -tulpn, etc.]

Task:
1. Identify the top 3 most probable root causes ranked by likelihood.
2. Provide safe, read-only CLI commands to confirm each hypothesis.
3. Provide the exact remediation steps and post-fix verification command.
```
